# 平台接入与验收说明

四个连接器均使用本人账号的平台官网流程。小红书和抖音发布图文，微博发布原生微博，B站发布动态；不把视频投稿或专栏草稿当作动态发布。

## 登录和会话

默认连接平时使用的 Google Chrome 144 或更新版本。先打开 Chrome，在地址栏输入 `chrome://inspect/#remote-debugging` 并开启远程调试，再到「平台账号」点击平台的连接按钮，在 Chrome 弹窗中允许连接。无需从命令行启动 Chrome 或安装扩展；Chrome 自身的连接授权和自动化控制提示仍会显示。未开启远程调试或未允许连接时，控制台显示设置指引，不会启动备用独立浏览器。

四个平台共享当前 Chrome 连接，各自使用本应用创建的可见标签页和 Chrome 当前登录的账号。重复打开会复用本应用已有的平台标签页，不接管用户原来打开的网页。未登录时，在平台官网标签页完成登录；控制台也会显示可用的官网二维码。扫码、手机确认或安全验证完成后，仍需等待控制台识别实际账号。小红书连接入口统一为创作中心，身份通过同源 `/api/galaxy/user/my-info` 核验；主站 `/user/me` 被拒绝不再阻断新连接。

打开控制台和读取连接状态不会自动连接或启动浏览器。点击发布时，控制台会连接当前 Chrome、复用或重新创建平台标签页，并核对实际账号，再显示内容与账号确认页。Chrome 必须保持运行，重新连接时可能再次要求授权。关闭标签页后，账号卡片保留“已绑定”和最近核验的公开资料；这不保证网站登录仍有效，操作前必须重新核验。登录过期或需要验证时保留文案并提示操作。

确认内容后、实际提交前仍会检查账号。如果连接或应用标签页在此期间关闭，会尝试重新连接当前 Chrome 并核对原账号；账号变化则停止发送，要求重新确认。连接与账号检查不会自动发送内容，也不会重试已经提交但结果不确定的请求。

默认本地数据目录：

| 平台 | 连接记忆标记 | 发布账本 |
| --- | --- | --- |
| 小红书 | `.data/xiaohongshu-chrome-connection` | `.data/xiaohongshu-publish-ledger.json` |
| 抖音图文 | `.data/douyin-chrome-connection` | `.data/douyin-publish-ledger.json` |
| 微博 | `.data/weibo-chrome-connection` | `.data/weibo-publish-ledger.json` |
| B站动态 | `.data/bilibili-chrome-connection` | `.data/bilibili-publish-ledger.json` |

可使用 `.env.local` 中的 `APP_DATA_DIR` 指定应用数据目录。登录信息由日常 Chrome 保管，本应用保存连接记忆与公开账号资料（UID、昵称、主页及头像地址），不复制 Cookie。旧 `.data/{platform}-profile` 配置原样保留，不会自动迁移、接管或删除；旧配置里的账号不会迁移到日常 Chrome，请在当前 Chrome 登录所需账号并核对。

「关闭此平台标签页」只关闭本应用创建的该平台页面，保留 Chrome 登录状态、连接记忆和账号绑定。绑定在重启本地服务后仍保留，缓存账号不能直接授权发布。「解除绑定」还会清除该平台的连接记忆和账号绑定，不退出 Chrome 中的网站账号，也不删除发布账本。要退出网站账号，请在官网操作。关闭本地 Node 服务只释放应用创建的标签页和调试连接，不退出日常 Chrome，也不关闭用户原有网页。

## 发布和部分成功

真实发布前准备好图片，并先保存本地草稿和本次请求编号；保存失败时不会提交平台。每个平台的请求编号独立。先核对当前账号，再核对该平台将发送的文字和图片。

连接器将图片交给官网上传控件，确认全部上传完成后才能提交。紧邻点击原生发送按钮前，服务端先把请求写入账本。点击后只有拿到明确的成功结果和可验证的帖子编号才保存成功回执；跳页或按钮点击成功本身不算发布成功。

多平台内容可能部分成功。成功平台保留回执，不再重复发送；其余平台单独处理。如果客户端断线或服务重启，控制台可从服务端回执恢复已确认结果。

多个控制台标签页会同步发布锁和回执，写入前核对最新本地记录，避免旧页面覆盖已经提交的文案。服务端也会拒绝同一内容编号在同一平台更换请求编号后再次发布。确实需要再发时，应复制为一条新草稿并重新核对。

如果本地发布元数据丢失，服务端可按内容编号恢复成功回执，但无法据此还原原文；控制台会提示当前本地文案可能与原文不同，需要通过原文链接核对。

结果待核实表示请求可能已送出。此时不要删除账本、替换请求编号或复制同样内容来绕过保护；先查看平台官网。“核对上次发布”和“核对操作结果”使用独立只读流程，只读取原请求、原账号和平台证据，不会触发首次提交或再次点击；旧后端未提供核对能力时会提示重启服务。当前没有自动判定「确认未发布」并清除待核实记录的功能。

## 平台规则

当前产品统一使用 4 张图片、单张 3 MB 的上限。微博、小红书和抖音连接器接收 JPG、PNG、GIF、WebP，仍以官网接受的格式为准；B站动态只接收 JPG、PNG、GIF，WebP 在确认页前拦截，不会自动转换动画。图片站点跨域限制导致链接无法读取时，应下载后从本地上传，服务端不会代理任意图片 URL。

小红书和抖音图文至少需要一张图片；小红书标题必填、最多 20 个 Unicode 字符，抖音标题必填、最多 30 个字符，正文均最多 1000 个字符。微博、B站动态将标题和正文用空行合并，B站合并内容最多 1000 个字符。所有平台需要文字，官网更严格的校验仍会阻止发布。具体错误会显示在对应平台操作中。

定时选择仍是本地计划，不会后台自动发帖。控制台已移除模拟发布；旧版本只有演示状态而没有真实回执的已发布内容会恢复为草稿。

## 修改与删除

每个平台的真实回执下提供修改文字和删除原文的操作。修改标题、正文时保留原图，不创建新帖子。平台没有编辑入口、原文仍在审核或账号无编辑权限时，控制台显示平台限制，保留当前回执。

修改与删除都需要重新确认原账号和目标原文。目标帖子来自服务端原发布账本；客户端不能传入任意帖子网址进行操作。实际操作通过官网原生按钮完成，提交前先持久化请求，取得明确结果后才记录修改时间或删除时间。超时或无法确认结果时保留原请求，不会自动重复点击。

小红书修改待核对时，先使用“核对操作结果”读取官网当前文字。需要再次应用保存的修改时，使用独立的“重新提交这次修改”并确认；系统先核对是否已经成功，再向同一篇原文提交同一份文字，保留当前原图。该操作不能用于重发笔记，也不能更换内容或账号。

在全部已发布平台确认删除前，控制台禁止删除原数据；任何平台仍有待确认的发布或变更请求也会阻止删除。本地删除前再次读取服务端四平台账本，避免页面过期或本地回执遗漏造成误删。删除平台原文与删除本地记录是两个独立步骤，服务端操作账本和删除墓碑仍保留。

本地内容存储兼容旧数组格式，并使用包含内容和删除标记的版本化记录，避免旧标签页重新写回已删除内容。在内容管理中可导出、导入 JSON 内容备份；导入前显示内容数量并确认，保留原内容编号、文案和图片。相同编号的普通草稿可以更新，已有真实回执或待核对操作的记录会保留；已删除的内容编号不会被备份恢复。登录凭据不在内容导出中。

## 验收边界

代码验证以确定性测试为主：注入平台响应、隔离 DOM 页面和虚拟账号，检查账号变化、图片失败、重复请求、原子落盘和回执恢复。平台只读探查用于确认官方编辑器、二维码和响应结构。

真实账号发布验收在用户授权范围内进行，验收记录必须区分实际成功、未提交失败与结果待核实。未做真实账号验收的平台不能据测试通过推断当前账号一定可发。

服务拒绝跨来源的变更请求，本地数据目录和发布账本不会通过应用静态服务暴露。遇到网站变更或需要官网验证时，连接器停止并提示在 Chrome 中的平台标签页处理。

隔离浏览器模式的验证结果不能直接用于判断复用日常 Chrome 时的实际行为。识别账号、加载二维码或进入发布确认页，也不代表已完成发布与删除验收；成功状态必须有对应的平台回执。

平台可能因网络、安全验证或账号权限限制登录与操作。控制台会展示返回原因并停止相应操作；小红书账号通过创作中心核验，避免主站身份接口受限时误判登录状态。
